## Deviations and limits retained for review

- No real YouTube, AI provider, Anki collection, user profile, Sudachi backend or installed dependency is used. DNS resolution is disabled in the new browser fixture; page requests are fulfilled locally or blocked. The unchanged existing browser suite uses its own local-only fixture and disposable profile.
- The generated tail is validated against a closed template/identifier schema, not the sketch's proposed JavaScript mini-parser. Prefix and trailer preservation, tail tampering, missing symbols and read-only snapshots have explicit self-checks. Nested functions (`sendSenseiQuestion`, modal/export handlers) are intentionally not exported or rewritten.
- Fake `innerHTML` only instantiates static ID-bearing UI scaffolding. It never strips tags or supplies a text/markup security oracle. Security assertions and export parsing use Chromium. Fake class/style counters count attempted writes, including no-ops; real P8 mutation records decide whether these cause native DOM mutations.
- The fake stores independent JSON snapshots and delivers callbacks asynchronously. Ten concurrent-save schedules vary callback turns with a seeded PRNG. The quota double approximates accounting with serialized object bytes; real Chromium is used for the failure/UI boundary. Omitted-callback fake storage errors are logged rather than emitted as unhandled Promise rejections, so the double does not assert Chrome's unhandled-rejection behavior.
- Timing is separate from accessor counts for P1 and unwrapped for adversarial P2. Normal render timing still includes the fake DOM and therefore cannot establish browser frame cost. First timed calls for general helpers follow fixture setup; only the separately recorded P2 typical first-call measurement is a fresh reading-engine context measurement. Do not call every `coldFirstCall` field a cold process launch.
- All 1,000 typical outputs are collected once per configuration per process, with a separate complete 1,000-render count block. Typical timing uses a fixed 20-line batch (15 measured samples), not 15 full-corpus sweeps. Long adversarial inputs at n≥4,000 use one warmup and three measured calls; other inputs use five warmups and 15 measurements. Parser `<` jobs use cold + three measured calls and no extra warmup. These changes bound pathological inputs without changing size or target.
- Whole-area event-loop delay includes fixture setup, output and asynchronous work. `maxBlockMs` on a timed row is measured synchronous call/batch duration; heap deltas include retained fake request logs. Heap deltas are observational and are not isolated product allocation measurements.
- The translation growth sequence is cumulative and the fake fetch recorder retains request strings. Cache entry count and hit behavior are firm; heap-by-entry attribution is limited. Card byte totals describe serialized payloads, not exact Chrome internal write amplification.
- P8 uses native production observers. It measures real render rebuilds/mutations, layout/task metrics and long tasks, but cannot expose observer callback invocation counts without changing the observer construction boundary. No production observer wrapper is installed. The 2,000 unrelated churn operations are append/remove pairs (4,000 native mutation records), not 2,000 total native records.
- Quota and hostile-read evidence live in browser regression rows, referenced by P8 instead of being executed twice. Default Anki control's transport relay is explicit; the configured-route assertion never relays or silently contacts an existing service on port 8765.
- The A12 workload is the requested 6,000-input subset, not the source review's 75,940 inputs; its difference count must not be compared with 452 as if the corpus were identical. The 500 bridge samples repeat a finite shape table; they are not 500 unique objects.
- Explicitly not covered: two different videos' embedded JSON selection; a real optional-permission grant prompt; a distinct ungranted real-browser worker outbound refusal (the manifest already grants every HTTP(S) origin); exact linguistic correctness; a parser-online UI timing path; zero-width-only reading inputs; a separate long-cue-text timeline size sweep; actual live CSP/script execution; real timer drift or network timeout latency. No deadline is inferred for requests without a signal. These are limitations, not accepted red product cases.
- The A06 enriched-save label is accepted as green under the proposal's expressly allowed local-storage disclosure outcome. Fallback romaji and a quote-only highlight input are benign characterization controls where no markup element is created; no false vulnerability is asserted for them.
- Timing rows with CV >25% are noisy and do not establish timing acceptance. Scaling-gate classification uses repeated per-process medians, CV, MAD separation and the unchanged slope/ratio targets. Absolute milliseconds remain observational/soft.

## Measurement recovery

The core pass found a UTF-8 chunk-decoding error in its merge (raw files intact), a fixed-sleep bridge fixture race, and third-process parser stress timeouts. The decoder and poll preconditions were corrected and independently verified; original raw/merged evidence is preserved. Three 55-second 160k parser timeouts remain unresolved after a separate 90-second VTT retry also timed out. They are HARNESS_ERROR/limitations, never accepted red product failures. Full details and exact commands are in `../../test-results-report.md` and `perf/recovery.json`. Final measurement elapsed time is 21.49 minutes.
