# LangPlay player panel and Jimaku subtitles

The requested reference is [Marsel204/LangPlay](https://github.com/Marsel204/LangPlay), inspected at `49647f7c0160c1bf548b80f9fc5b7e4b64a440f7` (3 November 2026). The implemented visual authority is its current `integrations/seanime/src/player-surface.css` and study renderer, rather than the older standalone player or proposed amber UI study.

The video caption uses the reference's white semibold Japanese, pink readings, transparent 18% charcoal glass, 8px backdrop blur, reflection, 18px corners and text shadows. The study panel uses the same charcoal background, lavender actions, compact word/reading/meaning hierarchy, per-word romaji and dictionary glosses, English sentence meaning, inline question row and explicit resume action. The existing reading engine, optional parser, AI model settings and card/export contracts remain available. Settings retains its existing system-appearance design.

## Behavior and acceptance

- Watching mode is Auto, Song or Episode, saved per video identity. Song prioritizes synced lyrics and suppresses episode-caption acquisition/Jimaku UI; Episode uses captions/Jimaku and ignores song caches and automatic lyric searches. Auto preserves the existing YouTube caption-first/lyric-fallback behavior and episode sources on other sites. The ready badge follows the active source. More → Find lyrics selects Song explicitly. Mode changes invalidate pending source ownership, clear incompatible captions and prevent stale lyric responses from starting new AI identification or blocking a new explicit search.

- The compact toolbar presents power, one reading dropdown, Subtitles, More and Close in one row. More groups repeat, import, lyrics and extension settings. Subtitle timing and appearance stay in the Subtitles panel, which dismisses the toolbar when opened.

- YouTube keeps automatic caption extraction and the existing explicit lyrics/import flows. Netflix, Prime Video, Disney+, Hulu, Crunchyroll and Vimeo attach controls to a visible HTML5 video. Jimaku and local files use that video's playback clock. This extension does not supply a video stream or change subscription access.
- Jimaku uses its documented raw `Authorization` API key header from extension Settings. Search supports anime/live-action titles and an optional episode filter. Users choose a file, inspect three parsed lines, and explicitly apply it. Existing subtitles stay active until the replacement is ready and applied.
- SRT, WebVTT, ASS, SSA and LRC import are supported. UTF-8, UTF-16 BOM and Shift_JIS are decoded. Downloads are capped at 10 MB, including streamed responses without a length header. Archives must be extracted externally. ASS positioning/styles and vector drawings are omitted from the learning text.
- Downloads are resolved from the provider's file list in the service worker, restricted to Jimaku HTTPS entry URLs; page messages cannot supply arbitrary download URLs. Subtitle credentials are not sent to downloads or video sites. Missing keys, HTTP/authentication/rate-limit errors, empty results and invalid subtitles show recovery text.
- Search and preview results belong to their video acquisition and request generation. Navigation discards old results. Each explicit application uses the existing manual source-ownership mechanism, so delayed captions or lyrics cannot displace it.
- Positive delay displays subtitles later; reset and first-line-to-playhead synchronization use the same clock convention. Delay is saved per video.
- English caption meaning is initially enabled and can be disabled independently of reading style. Translation uses Google Translate first, with the saved 9Router model or combo as an automatic sentence fallback on failure. Requests share pending work, use bounded caching and allow four concurrent worker requests. Google HTTP 429 responses trigger a 1–5 minute cooldown, respecting Retry-After within those bounds. Explicit retry remains available if both providers fail; its tooltip explains the error. Ordinary reading and dictionary lookup do not invoke generative AI.
- The saved **Subtitle size** slider beside background opacity scales Japanese, readings and English from 50–200% against the existing responsive 100% baseline. Dragging previews immediately without replacing word nodes; releasing the control saves it across pages/sites. **Default size** restores 100%, and native keyboard range controls remain available.
- Saved horizontal/vertical position controls move the entire Japanese/readings/English block within the available video region. Horizontal 0–100% spans Left → Right; vertical 0–100% spans Bottom → Top. Default position restores horizontal 50%, vertical 0%. Positions preview immediately and save after adjustment, retain word nodes, preserve lower clearance for letterboxing and narrow bottom sheets, and stay bounded after resizing/fullscreen. Study and Subtitles panels do not shift the caption block horizontally; 50% remains the full video's center with either panel open.
- Clicking a Japanese word pauses playback and freezes its sentence. Close/Escape keeps it paused. Resume explicitly resumes the current video. Fullscreen keeps controls/panels inside the player; narrow study becomes a scrollable lower sheet. Opacity changes retain word nodes and event listeners. Focus, reduced motion, reduced transparency, high contrast and forced colors are supported.

## Verification scope

The production extension is tested in Chromium using intercepted YouTube and video-site pages, a small generated playable WebM fixture, deterministic Jimaku/Google responses and disposable profiles. This verifies the extension's real injection, worker messaging, rendering and media interactions without real accounts. Unit regressions exercise malformed/provider errors, unsafe URLs, bounded downloads, decoding, parsing, request sharing and late translation results. The existing AI, Anki, caption transport and native-launcher checks remain applicable.

Live subscription-site DOMs and account-authenticated Jimaku searches/downloads are not verified by fixtures. Contextual Sudachi accuracy still depends on the optional backend. A browser's native fullscreen of the video element alone cannot display extension DOM; site-provided container fullscreen is the supported overlay surface.
